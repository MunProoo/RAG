RAG Pipeline 구조와 동작 가이드

Open WebUI, ChromaDB, BM25, 리랭커와 Ollama가 어떻게 연결되는지 쉽게 설명한다.

사용자 질문과 의미가 비슷한 문서 조각을 찾은 다음, 그 조각을 LLM에 참고자료로 제공해 답변하게 하는 시스템이다.

Open WebUI

사용자가 질문하고 답변을 확인하는 채팅 화면이다. 대화와 설정은 PostgreSQL에 저장하고 Redis를 캐시로 사용한다.

Pipelines

질문 처리, 문서 검색, 참고 문맥 구성, Ollama 호출을 담당하는 핵심 백엔드다.

Indexer

원본 문서를 작은 청크로 나누고 ChromaDB와 BM25 인덱스를 만드는 배치 작업이다.

Ollama

Docker 외부 Windows 호스트에서 LLM을 실행한다. 컨테이너에서는 host.docker.internal:11434로 접근한다.

  • rag_pipeline.py: 질문을 받아 검색하고 답변을 생성한다.
  • index_documents.py: 문서를 ChromaDB와 BM25에 저장한다.
  • eval_retrieval.py: 골든 질문셋으로 검색 품질을 평가한다.
  • test_rag_regression.py: 검색과 스트림 회귀를 검사한다.

1. 문서를 검색 가능하게 준비하는 과정

담당 파일은 rag/scripts/index_documents.py다.

원본 문서PDF·MD·TXT
→
내용 추출페이지·섹션
→
청킹480 / 중첩 80토큰
→
임베딩BAAI/bge-m3
→
저장ChromaDB + BM25

ChromaDB 저장

각 문서 청크는 BAAI/bge-m3 모델을 통해 숫자 벡터로 변환된다. 의미가 비슷한 문장은 벡터 공간에서도 가까워지기 때문에 단어가 완전히 같지 않아도 검색할 수 있다.

본문과 함께 파일명, 페이지, 섹션, 문서 종류, 제품, 프로토콜 세대와 버전도 메타데이터로 저장한다.

BM25 인덱스

동일한 청크를 bm25_index.json으로 저장한다. BM25는 API명, 파라미터, 명령어, 버전처럼 정확한 문자열 검색을 보완한다. 

docker compose run --rm indexer \
  python /app/scripts/index_documents.py /app/docs --reset

2. 질문 한 건이 처리되는 과정

핵심 진입점은 rag/pipelines/rag_pipeline.py의 Pipeline.pipe()다.

1

후속 질문 문맥화 LLM

“그거 자세히 설명해줘”처럼 대상이 생략된 질문을 이전 대화를 반영한 독립적인 질문으로 바꾼다.

그거 자세히 설명해줘
→ Alpeta 프로토콜의 Param3을 자세히 설명해줘
2

검색 질문 재작성 LLM

질문을 검색에 유리한 2~4개의 표현으로 재작성하고 도메인 동의어나 버전 표현을 추가한다.

3

검색 범위 결정 규칙 기반

질문에 있는 “Alpeta”, “프로토콜”, “신규” 같은 단어로 검색 범위를 제한한다.

product = alpeta
document_type = protocol
protocol_generation = current
4

ChromaDB 벡터 검색 LLM 아님

질문을 BGE-M3로 벡터화한 뒤 문서 벡터와 코사인 유사도를 비교해 의미가 가까운 청크를 찾는다.

5

BM25 키워드 검색 LLM 아님

Param3, API 이름, 버전처럼 정확한 문자열이 중요한 결과를 찾는다.

6

RRF 병합과 리랭킹 LLM 아님

벡터 검색과 BM25 순위를 RRF로 합친다. 그다음 BAAI/bge-reranker-v2-m3 CrossEncoder가 질문과 후보를 다시 비교해 정렬한다.

7

참고 문맥 구성 코드 처리

출처별 청크 수와 전체 글자 수를 제한하고 질문 초점에 맞는 청크를 참고 문서 블록으로 조립한다.

8

최종 답변 생성 LLM

Ollama가 검색된 참고 문서, 질문, 최근 대화를 받아 최종 답변을 스트리밍한다.

LLM의 역할

LLM이 하는 일

  1. 후속 질문의 생략된 문맥 보완
  2. 검색용 질문 재작성
  3. 검색 문서를 읽고 최종 답변 작성

독립적인 일반 질문은 문맥화가 생략되므로 보통 두 번 호출된다.

LLM이 하지 않는 일

  • 임베딩: BGE-M3
  • 벡터 검색: ChromaDB
  • 키워드 검색: BM25
  • 순위 병합: RRF
  • 재정렬: BGE CrossEncoder

현재 Docker Compose 기준 모델

  • 질문 재작성 및 문맥화: qwen3.5:4b
  • 최종 답변 생성: qwen3.5:4b
  • 임베딩: BAAI/bge-m3
  • 리랭커: BAAI/bge-reranker-v2-m3

운영 시 기억할 사항

  1. 문서를 추가하거나 수정하면 인덱서를 다시 실행한다.
  2. 임베딩 모델 변경 시 --reset으로 전체 재인덱싱한다.
  3. 청킹이나 메타데이터 분류 규칙 변경 시에도 재인덱싱한다.
  4. 검색 로직 변경 후 회귀 테스트와 골든 질문셋 평가를 실행한다.
  5. pipelines와 indexer의 chromadb 버전을 동일하게 유지한다.
# 검색 회귀 테스트
docker compose run --rm --no-deps --entrypoint python \
  indexer /app/scripts/test_rag_regression.py

# 골든 질문셋 검색 평가
docker compose run --rm --no-deps --entrypoint python \
  indexer /app/scripts/eval_retrieval.py
Indexer는 문서를 검색 DB로 만들고, Pipeline은 관련 문서를 찾으며, Ollama는 찾은 내용을 읽고 답변한다.
