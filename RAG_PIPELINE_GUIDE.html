Open WebUI, ChromaDB, BM25, 리랭커와 Ollama가 어떻게 연결되는지 설명한다. (Markdown과 동기화, 2026-08)

Open WebUI

사용자가 질문하고 답변을 확인하는 채팅 화면이다. 대화와 설정은 PostgreSQL에 저장하고 Redis를 캐시로 사용한다.

Pipelines

질문 처리, 문서 검색, 참고 문맥 구성, Ollama 호출을 담당하는 핵심 백엔드다.

Indexer

원본 문서를 작은 청크로 나누고 ChromaDB와 BM25 인덱스를 만드는 배치 작업이다. 목차·카탈로그 페이지는 더 큰 청크로 저장한다.

Ollama

Docker 외부 Windows 호스트에서 LLM을 실행한다. 컨테이너에서는 host.docker.internal:11434로 접근한다. qwen3.5는 think:false를 유지한다.

ChromaDB 저장

각 문서 청크는 BAAI/bge-m3 모델을 통해 숫자 벡터로 변환된다. 메타데이터에는 파일명, 페이지, 섹션, 문서 종류(protocol/install/user_guide/api), 제품, 프로토콜 세대·버전이 들어간다.

목차·명령 카탈로그처럼 짧은 번호/hex 행이 밀집한 PDF 페이지는 섹션을 쪼개지 않고 더 큰 청크로 인덱싱해 “전부 리스트”가 잘리지 않게 한다.

BM25 인덱스

동일한 청크를 bm25_index.json으로 저장한다. BM25는 API명, 파라미터, 명령어, 버전처럼 정확한 문자열 검색을 보완한다.

Swagger md 재생성

docker compose run --rm --no-deps --entrypoint python indexer \
  /app/scripts/swagger_yaml_to_md.py \
  --input /app/docs/swagger_kr.yaml \
  --output /app/docs/swagger_kr.md

docker compose run --rm indexer \
  python /app/scripts/index_documents.py /app/docs --reset
docker compose up -d --force-recreate pipelines

2. 질문 한 건이 처리되는 과정

핵심 진입점은 rag/pipelines/rag_pipeline.py의 Pipeline.pipe()다.

1

후속 질문 문맥화 LLM

“그거 자세히 설명해줘”처럼 대상이 생략된 질문을 이전 대화를 반영한 독립적인 질문으로 바꾼다.

2

검색 질문 재작성 LLM

질문을 검색에 유리한 표현으로 재작성하고, 자동화 빌드·FaceWT·UI 표기 등 의도별 키워드를 확장한다.

3

검색 범위 결정 규칙 기반

프로토콜/가이드/설치 키워드로 범위를 제한한다. API 의도에서는 document_type=api와 product 필터 완화를 적용한다. User Guide 절차는 Protocol/NSIS 혼입을 막는다.

product = alpeta
document_type = protocol | user_guide | install | api
4

ChromaDB 벡터 검색 LLM 아님

질문을 BGE-M3로 벡터화한 뒤 문서 벡터와 코사인 유사도를 비교해 의미가 가까운 청크를 찾는다.

5

BM25 키워드 검색 LLM 아님

Param3, API 이름, 버전처럼 정확한 문자열이 중요한 결과를 찾는다.

6

RRF 병합과 리랭킹 LLM 아님

벡터와 BM25 순위를 RRF로 합친 뒤 BAAI/bge-reranker-v2-m3가 재정렬한다. 기술 토큰·경로 역할·API 근거에 가점을 준다.

7

참고 문맥 구성 코드 처리

출처별 청크·글자 수 제한, 목록 완결성, 자동화 섹션 구간 강제 포함, 수동 절차 제거 등을 적용해 참고 블록을 만든다.

8

최종 답변 생성 LLM

Ollama가 참고 문서와 질문을 받아 스트리밍한다. 첫 yield 전 긴 동기 작업이 있으면 UI가 무응답처럼 보일 수 있다.

LLM의 역할

LLM이 하는 일

  1. 후속 질문의 생략된 문맥 보완
  2. 검색용 질문 재작성
  3. 검색 문서를 읽고 최종 답변 작성

독립적인 일반 질문은 문맥화가 생략되므로 보통 두 번 호출된다.

LLM이 하지 않는 일

  • 임베딩: BGE-M3
  • 벡터 검색: ChromaDB
  • 키워드 검색: BM25
  • 순위 병합: RRF
  • 재정렬: BGE CrossEncoder
  • 역할·절차·목록 규칙: 코드

현재 Docker Compose 기준 모델

  • 질문 재작성 및 문맥화: qwen3.5:4b
  • 최종 답변 생성: qwen3.5:4b
  • 임베딩: BAAI/bge-m3
  • 리랭커: BAAI/bge-reranker-v2-m3

운영 시 기억할 사항

  1. 문서를 추가하거나 수정하면 인덱서를 다시 실행한다.
  2. 임베딩·청킹·메타데이터 변경 시 --reset 재인덱싱한다.
  3. 검색 로직 변경 후 회귀(약 60개)와 골든 평가를 실행한다. 평가는 출처+필수 키워드. [PLF-20260801-002]
  4. pipelines와 indexer의 chromadb 버전을 동일하게 유지한다.
  5. 답변이 점만 보이면 qwen think:false·빈 content를 확인한다. [PLF-20260801-001]
  6. 도우미가 안 보이면 pipelines URL·chat 스키마·config를 확인한다. [PLF-20260802-001]
  7. 품질 작업 전후 기준선·pipe 원문을 artifacts에 남긴다. [PLF-20260801-003]
  8. PL 작업 전 PL_FAILURE_LOG.md 활성 예방 체크리스트를 읽는다.
# 검색 회귀 테스트
docker compose run --rm --no-deps --entrypoint python \
  indexer /app/scripts/test_rag_regression.py

# 골든 질문셋 검색 평가
docker compose run --rm --no-deps --entrypoint python \
  indexer /app/scripts/eval_retrieval.py
